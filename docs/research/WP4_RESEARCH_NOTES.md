# WP4 Research Notes

WP4 intentionally favors real public repositories over synthetic fixtures.

A quick external scan confirms that public TypeScript projects and fixture-oriented repositories are plentiful, so there is no need to manufacture all validation inputs. Repository selection should still be made deliberately and pinned for reproducibility.

The validation methodology follows a simple principle:

> Real repositories + pinned commits + preserved raw output are more credible than a hand-crafted demonstration designed to make the tool succeed.

WP4 does not attempt to establish statistical generalizability. Three repositories and roughly nine changes are a feasibility/usefulness sample.

If WP4 succeeds, a later validation round can broaden the corpus.

If WP4 fails, increasing the sample size should not be used to rationalize obviously poor signal.
