# Success, Stop, and Expansion Criteria

## Success

- implementation remains small
- no custom analysis engine
- deterministic results
- findings trace to existing tools
- missing evidence is honest
- CLI is useful enough to run voluntarily
- no cloud/account/API key
- another developer can understand how to run it

## Stop

Stop if function correlation needs substantial custom analysis, evidence is too unreliable, output adds little beyond existing tools, ordinary repo support requires a large framework, maintenance starts resembling a platform, or the project stops being useful/enjoyable as research.

Stopping is a successful research outcome.

## Expansion

Add a capability only after a real use case demonstrates value, an existing deterministic tool can supply it, integration remains small, and it improves a concrete finding.

Do not design for other languages now. A second language, if ever attempted, should reveal which abstractions are actually real.
