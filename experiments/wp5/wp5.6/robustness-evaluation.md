## Boundary map (what works / doesn't / untested)

**Works** (verified):
- TypeScript single-package repos
- vitest v8 coverage + Istanbul coverage
- Function-level attribution with container-method identity (post-WP5.3 A07)
- Path-suffix matching with exact-match precedence (post-WP5.3 A08)
- 0/1/2/3/4/11/108/196 changed-function count
- CC range observed: 1–36
- Coverage range observed: 0%–100% (zero distinct from absent per INV-01)
- Threshold 15 vs 30 (policy, not evidence)

**Doesn't work / unresolved** (boundaries):
- apollo-client coverage generation: Jest reporter failure (WP4R §Known Limitations) — out of scope for WP5.6
- Test-file coverage: not generated by either vitest v8 or Istanbul in WP4R runs; post-WP5.3 C03 discovery surfaces them as `skipped`

**Untested** (out of WP5.6 scope):
- Monorepos, pnpm workspaces
- Windows/Unicode paths
- Symlinks
- Generated code (codegen output)
- Source maps
- Languages other than TypeScript/JavaScript
- Coverage providers other than Istanbul/v8

## Performance

Per-case runtime (analysis only, excluding clone/coverage generation):
- hono-01: <100ms
- hono-02: ~200ms
- hono-03: ~300ms
- sup-a: ~3s (196 fns)
- sup-b: ~500ms

Coverage generation runtime is **out of scope** for the deterministic engine per project-wide "caller owns coverage" boundary.
