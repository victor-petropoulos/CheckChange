# D2 Baseline/Delta Plan

## Goal
Implement `delta` subcommand that compares two **EvidenceOutput** runs (v0.5 schema) and emits a **sidecar DeltaOutput** — an evidence diff, not a score diff. Pure comparator in `src/delta.ts`; thin CLI wiring in `src/cli.ts`. Additive only — schema 0.5 frozen, gate semantics frozen, engine files untouched.

## Architecture
- **src/delta.ts** (new, pure):
  - `compareEvidenceOutputs(baseline: EvidenceOutput, current: EvidenceOutput): DeltaOutput` — pure, deterministic, no I/O
  - `compareFromFiles(baselinePath, currentPath): Promise<DeltaOutput>` — file I/O with `isWithinCwd` + `MAX_SIZE=100MB` guards (reuse `src/coverage.ts:25` + `src/coverage-providers/lcovProvider.ts:11`)
  - Identity key: `file:method:lineStart` (`src/evidence.ts:138`)
  - Fingerprint diff: `diagnostics.fingerprints[key]` mismatch (`src/evidence.ts:125-141`)
  - Deltas: `cc`, `crap`, `coverage` (null vs 0 distinguished per INV-01 `evidence-contract.md:159-161`)
  - Rule transitions: `PASS↔WARN↔NOT_EVALUATED` per function; aggregate `gateTransition`/`completenessTransition` as strings (informational only, **no gate mutation** per Q6 `mem:44649`)
  - Provenance: bundle both sides' `diagnostics.lineage` + `quality` (trimmed, no absolute paths)
  - Output arrays sorted by key for byte-identical determinism

- **src/cli.ts** (extend `runDelta`):
  - Arg parsing: `--baseline <path> --current <path> [--json]` (file-pair primary per P8 spec)
  - `--json` → `console.log(JSON.stringify(delta, null, 2))`
  - Default → human summary: `added X, removed Y, changed Z; gate: PASS→WARN` (mirrors `runExplain` dual mode `src/cli.ts:378-388`)
  - Never emits EvidenceOutput fields (`gate`, `completeness`, `coverageErrorReason`, `schemaVersion:0.5`)

## Interfaces
```ts
// src/delta.ts exports
interface DeltaOutput {
  command: "delta";
  schemaVersion: "0.5";              // delta schema version
  inputs: {
    baseline: { base: string; analysisStatus: string; gate: string|null; changedFunctions: number };
    current:  { base: string; analysisStatus: string; gate: string|null; changedFunctions: number };
    thresholds: { baseline: number; current: number; equal: boolean };
  };
  summary: {
    added: number; removed: number; changed: number; unchanged: number;
    gateTransition: string|null;
    completenessTransition: string|null;
  };
  functions: {
    added: Array<{ key: string; current: ChangedFunction; ruleResult?: RuleResult }>;
    removed: Array<{ key: string; baseline: ChangedFunction; ruleResult?: RuleResult }>;
    changed: Array<{
      key: string;
      baseline: ChangedFunction;
      current: ChangedFunction;
      fingerprintChanged: boolean;
      deltas: { cc: number|null; crap: number|null; coverage: number|null };
      ruleTransition: string|null;
    }>;
    unchanged: string[];
  };
  provenance?: {
    baseline: { lineage: DiagnosticLineageEntry[] | null; quality: DiagnosticQuality | null };
    current:  { lineage: DiagnosticLineageEntry[] | null; quality: DiagnosticQuality | null };
  };
}
```

## Open Questions / Risks
1. **Input mode**: file-pair (`--baseline/--current`) primary per research; dual `--base` refs (re-run engine twice) deferred — adds git/coverage nondeterminism
2. **Key stability**: `file:method:lineStart` breaks on rename/move; fingerprint diff mitigates; no fuzzy matching v1
3. **Threshold mismatch**: if `policy.crapThreshold` differs, rule transitions confounded — surface `thresholds.equal:false`, do not normalize
4. **Pre-0.5 artifacts**: missing `diagnostics` → degrade gracefully, note `lineage: null` in provenance
