# WP4.2 — Composed Evidence Implementation — Plan

## Objective
Implement WP4.1 COMPOSE decision without expanding scope: Git intervals + core parser CC + existing Istanbul JSON + tiny CRAP + existing rule + new status semantics.

## Hard Boundary
Consumes analysis, does not perform source analysis. Allowed: direct core usage, reading Istanbul JSON, interval attribution, CRAP math. Forbidden: custom TS parser, custom CC, coverage instrumentation, target test execution, discovery.

## Evidence Flow
- Git: retain git diff -U0 parsing
- Function CC: use crap-typescript-core@0.5.0 directly (fields file, method, lineStart, lineEnd, cc)
- Coverage: read only coverage/coverage-final.json, if absent -> null (NOT_EVALUATED), if malformed -> FAILED/null/INCOMPLETE
- Attribution: Istanbul statement/branch spans -> method via interval overlap, no TS parsing
- CRAP: CC^2*(1-cov)^3+CC

## Status Contract
analysisStatus: SUCCESS|UNSUPPORTED|FAILED
gate: PASS|WARN|null
completeness: COMPLETE|INCOMPLETE|NOT_APPLICABLE

Examples per spec: SUCCESS/PASS/COMPLETE, SUCCESS/PASS/INCOMPLETE, UNSUPPORTED/null/NOT_APPLICABLE, FAILED/null/INCOMPLETE

## Schema
Increment to 0.2, capabilities: git, complexity, coverageArtifact (not old crapTypescript)

## Dependencies
Pin @barney-media/crap-typescript-core@0.5.0 already transitive, ensure direct dep.

## Tests 17 required
See plan tasks.

## Compatibility
WP0 fixture, one real TS repo with coverage artifact, one without.

## Forbidden
No test execution, coverage generation, Vitest/Jest discovery, package manager orchestration, JS support, baseline/delta, new rules, etc.
