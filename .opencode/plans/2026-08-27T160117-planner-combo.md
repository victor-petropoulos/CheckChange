# Planner Combo Plan

## Context

- planner currently `mtplx/mtplx-qwen36-35b-a3b-optimized-balance` — single model, no fallback, single point of failure
- Local server outage / memory pressure → planner dies, blocks orchestrator
- All peer agents (implementer, tester, reviewer, documenter, researcher) use 9router combos with fallback chains
- Documenter recently migrated to `9router/ONLINE-Documenter` combo (7-model chain) — same pattern requested for planner

## Why a combo (not single model swap)

1. **Reliability**: single-model mtplx dies if local server down; combo has 6 fallbacks
2. **Reasoning depth**: planning needs strong-reasoning models; combo head = Nemotron Ultra (proven reasoning)
3. **Context buffer**: plans read many files; 9router combos expose 128k-262k context models
4. **Quality tier**: planner is on the critical path (bad plan → wasted implementer/tester runs); online quality > local alone

## Combo: ONLINE-Planner

Models (fallback strategy, order = preference):

| # | Model | Why this slot |
|---|-------|---------------|
| 1 | `openrouter/nvidia/nemotron-3-ultra-550b-a55b:free` | **Primary.** Reasoning + tools, 128k ctx. Highest quality of Nemotron family. Same head as documenter combo (proven live). |
| 2 | `kgw/nvidia/nemotron-3-super-120b-a12b:free` | **Reasoning mid-tier.** 128k, tool-capable, reasoning. Proven in doc combo (was the live-resolving model on smoke test). |
| 3 | `openrouter/z-ai/glm-5.2:free` | **Planning specialist.** 200k ctx, reasoning (zai format), strong structured-output reputation. Drops to here if Nemotrons rate-limit. |
| 4 | `groq/openai/gpt-oss-120b` | **Fast mid-tier.** Reasoning + tools, 128k, fast Groq inference. Good for quick planning. |
| 5 | `groq/qwen3.6-27b` | **Instruction-following + huge ctx.** 262k ctx, reasoning (qwen format), strong on structured-output. Buffer for long plans. |
| 6 | `local/mtplx-qwen36-35b-a3b-optimized-balance` | **Local last resort.** Same model planner had before, keeps door open if all online down. |

Excluded vs ONLINE-Documenter:
- `oc/nemotron-3.5-lightning-free` — lighter, less reasoning; planner wants depth not speed
- `oc/nemotron-3-ultra-free` — same Nemotron Ultra head as slot 1, redundant
- `kr/qwen3-coder-next` — code-gen specialist, not planning

Why slot 3 = GLM-5.2 not gpt-oss:
- Documenter combo puts gpt-oss at slot 4; planner wants a **reasoning-strong** model in slot 3 to hold the line if both Nemotrons fail. GLM-5.2 reasoning format + 200k ctx > gpt-oss for plan structure.

## Mirror Documenter Pattern

Same structure as the recent documenter migration (see `agents/documenter.md.bak.20260827T122441` → current `agents/documenter.md`):
- `model: 9router/ONLINE-Planner` (replaces single `mtplx/...`)
- `temperature: 0.3` (deterministic planning)
- `steps: 30` (planning needs reads + context7 + cavemem + grill-me)
- All existing permissions preserved (read-only except `.opencode/plans/*`)

## Risks

1. **Head model rate-limits** (Nemotron Ultra free tier) → falls to Nemotron Super, then GLM-5.2. Acceptable; combo absorbs.
2. **Tool/skill invocation differences across combo members** — Nemotron/GLM/gpt-oss all support tool_call=true (verified via 9router /v1/models). mtplx local also tool-capable. No regression risk.
3. **Reasoning format variation** — interleaved `reasoning_content` is what opencode/AI-SDK expects; all 6 models support it. Planner already handles reasoning content (mtplx has it).
